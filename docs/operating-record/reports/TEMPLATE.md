# Personal Fitness OS: milestone checkpoint report

Copy this file to `YYYY-MM-DD-milestone-Cn.md`; fill the fields from evidence at that milestone. This is a future report form, not current evidence. Keep previous reports immutable and link corrections/superseding reports.

| Field | Required entry |
| --- | --- |
| Scope | Product/Workspace ID, affected Components/books and actual environment/channel |
| Milestone / checkpoint | Outcome and C0 through C5 gates touched |
| Source | Repository, exact SHA or full unversioned snapshot digest; source/asset custody |
| Date and people | Actual verification timestamp, author, accountable owner and reviewer |
| Change and rationale | What changed and why; relevant decision and previous report |
| Evidence state | unknown / planned / documented / verified / failed / not-applicable with reason |
| Verification | Command or human procedure, tool versions, exit/result, artifact/digest and limits |
| Recovery | Applicable RTO/RPO, backup source, measured restore outcome and missing work |
| Release/observation | Actual version/artifact hash, destination, release receipt, observation window and MetadataDB acknowledgement, when applicable |
| Privacy/rights/access | Applicable approvals and safe evidence locators; keep secrets and restricted source out |
| Open gaps | Responsible owner, explicit due date chosen by that owner, blocking checkpoint |
| Signoff | ship / revise / hold for the named scope, decision maker, rationale and date |
| Handoff | What another approved maintainer reproduced; next checkpoint and trigger |

Use [checklist](../checklist.md), [architecture](../architecture.md), [operations](../operations.md) and [recovery](../recovery.md). Update their current state alongside this report. A docs merge, mechanical build, private release and public publication are different outcomes; record only what happened.
